# Studio — Design System

Sleek, editorial, metric-forward. Bold where it counts, muted everywhere else.
**No gradients. Shadows used sparingly and only for genuinely floating layers.**
Depth comes from hairline borders, surface tints and generous space — not blur.

---

### Course palette
Seven muted hues, **computed rather than eyeballed**. Generated by search over
OKLCH and verified with the dataviz validator, minimising chroma subject to
passing every check — so it is as muted as it can be while still legible.

| Slot | Hex | Course |
|---|---|---|
| rust  | `#8A4430` | Coaching Software Teams |
| ochre | `#B28944` | PSI |
| sage  | `#3D6924` | RMT |
| teal  | `#0C9F8B` | Placement Year Review |
| slate | `#2D6FA0` | Functional Programming |
| plum  | `#A284C6` | Constraint Programming |
| rose  | `#A35760` | Project |

Validator result (light, surface `#FCFCFB`) — **all six checks pass, no warnings**:

```
[PASS] Lightness band       all 7 inside L 0.43–0.77
[PASS] Chroma floor         all 7 >= 0.1
[PASS] CVD separation       worst adjacent #A284C6↔#2D6FA0 ΔE 10.8 (protan) · tritan 11.6
[PASS] Normal-vision floor  worst adjacent #2D6FA0↔#0C9F8B ΔE 15.8 (normal)
[PASS] Contrast vs surface  all 7 >= 3:1
```

Colours are assigned **in course order**, so two courses adjacent in any legend
are exactly the pairs the validator checked for CVD separation.

Note this palette is deliberately distinct from `--rust-500`: the primary is
reserved for interactive elements, so a course accent is never mistaken for a
control. Each course stores its own hex, so an eighth course is just a new
value — nothing is positional.

**Colour is never the only carrier of identity.** Every course accent appears
beside its name, and charts direct-label their categories (see §7).

### Contrast
All body text meets WCAG AA (4.5:1) on its own surface; `--n-500` on `--n-0`
is 5.1:1. Progress fills carry a text label or adjacent numeral — colour is
never the only carrier of meaning.

## Wordmark

**Studio** — study + IO. Set entirely in Fraunces, with "io" in `--rust-500`
so the pun survives in colour alone. Beside it: the progress-ring mark, and
`26/27` in the numeric face. Component: `components/Wordmark.tsx`.

**Tab icon** — a cream house on a rust tile (`app/icon.svg`), also shipped as
`favicon.ico` (16/32/48) and `apple-icon.png` (180), because Safari doesn't
reliably use SVG favicons.

## 2. Typography

Three families, each with one clear job. Loaded via `next/font` (self-hosted,
no layout shift, no external request at runtime).

| Role | Family | Notes |
|---|---|---|
| **Display** | Fraunces | Variable soft-serif. Page titles, card headings, big empty-state statements. `wght 400–700`, `opsz` set high for large sizes, `SOFT 0`, `WONK 0` for restraint. Gives the app an editorial voice instead of a generic-dashboard one. |
| **UI / body** | Inter | Everything functional: labels, buttons, table text, prose. |
| **Numeric** | JetBrains Mono | Timer, stat numerals, durations, percentages. Tabular by nature, so digits never jitter as they tick. |

### Scale
A 1.25 ratio, rounded to whole pixels.

| Step | Size / line-height | Typical use |
|---|---|---|
| `display` | 44 / 48 | home page greeting |
| `h1` | 34 / 40 | page title |
| `h2` | 26 / 32 | section heading |
| `h3` | 20 / 28 | card heading |
| `body-lg` | 17 / 26 | lead paragraph |
| `body` | 15 / 23 | default |
| `sm` | 13 / 19 | secondary, metadata |
| `xs` | 11 / 16 | labels, uppercase eyebrows (`0.08em` tracking) |
| `stat` | 36 / 40 mono | headline metric |
| `stat-sm` | 22 / 26 mono | inline metric |

## 3. Space, radius, border

- **Space scale** (px): 2, 4, 6, 8, 12, 16, 20, 24, 32, 40, 56, 72.
- **Radius**: `sm 6` inputs/chips · `md 10` buttons/cards · `lg 14` panels · `full` pills.
- **Borders**: 1px `--n-100` default, `--n-200` for emphasis. This is the primary
  depth cue.
- **Shadow**: exactly two, both barely-there, reserved for layers that genuinely
  float above the page.
  - `--shadow-pop` — dropdowns, popovers: `0 4px 16px -4px rgb(26 23 20 / 0.10)`
  - `--shadow-modal` — dialogs: `0 16px 48px -12px rgb(26 23 20 / 0.18)`
  - Cards get **no** shadow. Ever.

## 4. Texture & flair

Restrained, structural, never decorative-for-its-own-sake.

1. **Dot grid** — a 24px `--n-200` dot lattice at 55% opacity behind the app
   background, masked to fade out toward content. Gives the page a drafting-paper
   feel and stops large empty areas reading as unfinished.
2. **Course accent rail** — a 3px left rail in the course's own colour on task
   rows and course cards. Does the colour-coding job without tinting whole
   surfaces.
3. **Progress bars** — squared-off ends, 6px tall, animated fill. The single
   place bold colour is allowed to dominate.
4. **Focus ring** — 2px `--rust-500` at 2px offset. Always visible, never removed.

## 5. Motion

| Duration | Easing | Use |
|---|---|---|
| 120ms | `ease-out` | hover, focus, colour change |
| 180ms | `cubic-bezier(.2,.8,.2,1)` | chips, checkbox ticks, chevrons |
| 260ms | `cubic-bezier(.2,.8,.2,1)` | panels, dialogs, accordion |
| 420ms | `cubic-bezier(.16,1,.3,1)` | progress bar fills, count-ups |

Rules:
- Animate `transform` and `opacity`. Never animate layout properties.
- Progress bars animate from their **previous** value, so ticking a checkbox
  visibly moves the bar — that feedback is the whole point of the app.
- Everything above collapses to `0.01ms` under `prefers-reduced-motion: reduce`.

## 6. Component conventions

- **Card** — `--n-0` surface, 1px `--n-100` border, `radius-lg`, 20px padding, no shadow.
- **Button** — 36px tall, `radius-md`, 13px/600 Inter.
  Primary = `--rust-500` on white. Secondary = `--n-0` with `--n-200` border.
  Ghost = transparent, `--n-50` on hover.
- **Input** — 36px, 1px `--n-200`, `radius-sm`, rust focus ring.
- **Checklist tick** — 18px square, `radius-sm`; unchecked is a `--n-300` outline,
  checked fills `--ok` and draws its path in 180ms.
- **Eyebrow label** — 11px, 600, `0.08em` tracking, uppercase, `--n-500`.
  Used above every stat and section heading.
- **Empty state** — Fraunces sentence + one primary action. Never a shrug emoji.

## 7. Charts

Built as inline SVG — no chart library, no CDN, no runtime dependency.

**Form follows the data's job.** Most panels on the stats page measure a single
magnitude over time, so they are single-series and use one hue (`--rust-500`)
rather than the categorical palette. The categorical palette is only for panels
where courses genuinely share an axis.

| Question | Form |
|---|---|
| How much did I study each day? | Bar chart, one series |
| Which hour of day is my best? | Bar chart, one series, 24 slots |
| Which weekday is best / worst? | Bar chart, one series, best & worst direct-labelled |
| How is focus trending? | Line + crosshair, one series |
| How is time split by subject? | Horizontal bars, **sorted, name-labelled** |
| Am I on track overall? | Stat tile / hero number — not a chart |

**Rules, applied everywhere:**
- **One axis.** Never two y-scales. Time and focus are separate panels.
- Categories are **direct-labelled**; colour reinforces identity, never carries it.
- Grid and axes recede: `--n-100` hairlines, `--n-400` tick labels, no chart border.
- Bars get 4px rounded ends at the data end only, anchored flat to the baseline,
  with a 2px surface gap between adjacent bars.
- Every chart has a hover layer with a tooltip. Hit targets are wider than the mark.
- Empty data renders an explicit empty state, never an axis with nothing on it.
- Sequential ramps (e.g. the hour heat strip) are **one hue, light → dark**, from
  the rust scale — never a rainbow.
